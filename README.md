# trust-ledger

When a paper's results are checked by machines (proofs verified by a proof assistant such as
[Lean](https://lean-lang.org), numerical scripts, formal models), a reader still has to ask: *which exact
statements were checked, by what, and who vouches that they say what the paper says?* trust-ledger keeps a
ledger that answers this. It lists every result of the paper and, for each, what it rests on: the
machine-checked proofs, the scripts and their outputs, results cited from other papers, assumptions that were
made but not proved, and the confirmations of named people who have personally checked that the formal
statement matches the text. Every item gets a *hash*, a short fingerprint computed from its exact content,
which changes if even one character of the content changes. The fingerprint of a result is computed together
with the fingerprints of everything it depends on, and so on up to a single *root* fingerprint for the whole
paper (this nested construction is called a Merkle tree, after its inventor). Change anything anywhere, and
the fingerprints of everything built on it, including the root, change too.

The root is printed in the paper's appendix next to a table with the status of every result, and can be
published elsewhere (for example in the arXiv comment field). Anyone who has the paper's supplementary files
can recompute it with the small program in this repository and see whether anything has changed since.
A person's confirmation stays valid only as long as the statement it was given for is unchanged: edit the
theorem or a definition it uses, and the confirmation is shown as *stale*. Nothing is hidden, and a result
without a confirmation is simply listed as not yet attested. What the ledger does *not* do is prove the
results correct or decide whether a formal statement means what the text means; that remains the job of the
people who attest. It makes it checkable what was checked, by whom, and what has changed since.

Status: early prototype. The method is described in the paper in `paper/` (draft).

* `ledger.py`: the whole tool. Python >= 3.11, standard library only; copy it into your project.
* `docs/FORMAT.md`: the normative format (hashing, node kinds, register). Other implementations
  should reproduce the same hashes.
* `lean/Dump.lean`: reads a Lean project and writes out its theorems and definitions, the exact proof objects
  the Lean checker accepted, and the axioms they use, so that they can be fingerprinted.
* `tex/ledgercheck.sty`: prints the root and a status appendix in the paper from two generated files.
* `paper/`: the paper that describes the method (`make paper`). It applies the method to itself: its theorems are
  checked in `formal/` (Lean, core library only, `make formal`), linked by `ledger/`, and the appendix
  "Evidence ledger" at the end of the paper is generated from that ledger.
* `examples/toy`: a hand-made project; `python3 ledger.py -C examples/toy status`.

## Use

```
ledger/ledger.toml       project config
ledger/claims.toml       claims, citations, assertions (human-written)
ledger/lean.json         generated by lean/Dump.lean
ledger/attestations.toml appended by `ledger.py attest`
ledger/lock.json         generated by `ledger.py lock`; commit it
```

```
python3 ledger.py status            # claims: evidence type, Lean status, attestation, register size
python3 ledger.py why CLAIM         # what a claim rests on, who attested
python3 ledger.py attest CLAIM --person NAME --level green --checklist A1,A2
python3 ledger.py addkey ID --person NAME --pub KEY.pub     # register an ssh key (optional signatures)
python3 ledger.py attest CLAIM --person NAME --level green --sign ~/.ssh/id_ed25519 --key ID
python3 ledger.py attest CLAIM ... --out me.att.toml --pub KEY.pub   # standalone attestation file
python3 ledger.py -P NAME verify-attestation me.att.toml --lock ledger/lock-NAME.json
python3 ledger.py attest --hypothesis NAME --person NAME --level green   # "this hypothesis is a known theorem"
python3 ledger.py lock              # write lock.json, print the root
python3 ledger.py verify            # recompute, compare with lock.json
```

Lean dump, from inside the Lake project after `lake build`:

```
printf 'Toy.thm\n' | lake env lean --run Dump.lean module=Toy root=Toy assume=Toy.BanachProp > ledger/lean.json
```

## In the paper

`ledger.py -P NAME tex` writes `ledger-NAME-root.tex` and `ledger-NAME-status.tex` into the
`[generated]` directory (excluded from the hashed source, so the root can sit in the document it
covers). `\usepackage[paper=NAME]{ledgercheck}` then appends the appendix "Evidence ledger" (status
banner, root, explanation, how to check, table) automatically. Without the generated files it prints
"UNSEALED DRAFT"; without the `paper=` option it does nothing. To switch it on without touching the
paper source (e.g. in a publish script), load it at the end of the preamble; a plain
`\RequirePackage` before `\documentclass` collides with classes that define `\toprule`:

    pdflatex '\AddToHook{begindocument/before}{\RequirePackage[paper=NAME]{ledgercheck}}\input{main}'

The table uses plain `tabular`s in chunks because `longtable`, `supertabular` and `p`-columns fail in
the two-column `quantumarticle` class.

## What it does and does not establish

It binds each claim to the exact proof objects, scripts and cited statements it rests on, and
makes any later change visible. It does not tell you that a statement means what the paper
means; that is what attestation is for, and an attestation is only as good as the person who
signs it. There is no PKI: accountability comes from publishing the root under the authors' names.

Tests: `python3 -m unittest discover -s tests`.

## Validation so far

On a private research Lean project (86 registered declarations, 709 in the dependency
closure): statuses and axiom sets agree with an independent export for all 86;
the dump is byte-identical across runs. Mutation test on a leaf theorem, with the claim attested
beforehand:

| mutation | result |
|---|---|
| unused `have` added to the proof, statement unchanged | `verify` fails (proof node, claim and attestation hashes changed); attestation stays *current*; other claims unchanged |
| statement weakened (`<` to `≤`) and proof replaced by `sorry` | claim status `sorry`, `sorry:` entry in the register, attestation *STALE*; other claims unchanged |
